# 앤시점심기술 미니게임 및 업적 시스템 상세 기획

> 이 문서는 사용자가 대화로 전달한 원본 기획서·개발 명세서 전문을 그대로 저장소에 옮긴 것이다.
> `docs/superpowers/plans/2026-07-28-remaining-achievements.md`, `docs/superpowers/plans/2026-07-28-expansion-achievements.md` 등
> 관련 계획서가 이 문서를 근거 자료로 참조한다.

## 1. 기획 개요
앤시점심기술의 미니게임은 '오늘의 메뉴 월드컵' 하나만 운영한다.
게임 종류를 여러 개 추가하기보다는 메뉴 월드컵을 실제 식당 선택 과정과 연결하고, 서비스 이용 과정에서 자연스럽게 업적이 달성되도록 구성한다.
업적 시스템의 목적은 사용자를 오래 붙잡아 두는 것이 아니라 다음 행동을 자연스럽게 유도하는 것이다.

* 평소 가지 않던 식당 방문
* 방문 기록 작성
* 리뷰와 메뉴 정보 등록
* 동료와 함께 먹기 참여
* 추천 기능과 메뉴 월드컵 사용
* 오래된 식당 정보 수정

업적을 달성하기 위해 의미 없는 행동을 반복하지 않도록 현금성 보상이나 과도한 경쟁 요소는 넣지 않는다.

## 2. 오늘의 메뉴 월드컵
### 2.1 기본 방식
등록된 메뉴 또는 식당을 토너먼트 형식으로 보여주고 사용자가 둘 중 하나를 선택한다.

```text
돈까스
VS
제육볶음
```

기본 구성은 8강으로 한다.

```text
8강 4경기
→ 4강 2경기
→ 결승 1경기
→ 최종 우승 메뉴
```

전체 선택 횟수는 7회이므로 약 20~40초 안에 완료할 수 있다.

### 2.2 월드컵 종류
메뉴 월드컵
메뉴 단위로 대결한다.

```text
김치찌개 VS 된장찌개
돈까스 VS 제육볶음
마라탕 VS 짬뽕
초밥 VS 덮밥
```

최종 우승 메뉴를 판매하는 주변 식당을 추천한다.

식당 월드컵
식당 단위로 대결한다.

```text
센텀국밥 VS 홍콩반점
돈카츠집 VS 기사식당
```

식당 사진, 대표 메뉴, 거리, 예상 가격대를 함께 표시한다.
초기에는 메뉴 월드컵만 구현하고, 식당 데이터와 사진이 충분히 쌓인 이후 식당 월드컵을 추가한다.

### 2.3 참가 메뉴 선정 기준
아무 메뉴나 완전히 무작위로 뽑으면 사용자가 선택하기 어려울 수 있으므로 다음 조건을 반영한다.

* 현재 영업 중인 식당의 메뉴
* 회사에서 설정한 최대 거리 이내
* 사용자가 제외한 식당 또는 메뉴 제외
* 당일 이미 먹은 메뉴 제외 가능
* 최근 자주 선택한 메뉴 일부 포함
* 잘 선택하지 않은 신규 메뉴 일부 포함
* 같은 종류의 메뉴만 과도하게 나오지 않도록 카테고리 분산

권장 구성은 다음과 같다.

```text
사용자 선호 메뉴 3개
새로운 메뉴 2개
인기 메뉴 2개
완전 무작위 메뉴 1개
```

### 2.4 월드컵 결과 화면
최종 결과는 단순히 우승 메뉴만 보여주지 않고 실제 점심 결정까지 연결한다.

```text
오늘의 우승 메뉴

제육볶음

홍천 님은 오늘 매콤하고 든든한 메뉴를 선택했어요.

추천 식당
1. 센텀기사식당 · 320m · 9,000원
2. 고기마을 · 510m · 10,000원
3. 오늘한상 · 680m · 9,500원
```

제공 버튼:

* 이 식당으로 결정
* 다른 식당 보기
* 월드컵 다시 하기
* 함께 먹을 사람 모집하기
* 결과 공유하기

### 2.5 취향 데이터 반영
월드컵 선택 결과는 사용자의 메뉴 취향을 추정하는 자료로 활용한다.
다만 한 번의 선택만으로 선호도를 크게 변경하지 않는다.
예시:

```text
월드컵 한 경기 선택: 선호도 +1
월드컵 최종 우승: 선호도 +3
실제 방문 완료: 선호도 +5
좋아요 평가: 선호도 +3
별로예요 평가: 선호도 -3
```

게임에서 우승했지만 실제 방문하지 않은 메뉴보다, 실제로 방문하고 긍정적으로 평가한 메뉴를 더 강하게 반영한다.

## 3. 업적 시스템 기본 구조
### 3.1 업적 분류
업적은 다음 일곱 가지 카테고리로 구분한다.

1. 시작
2. 방문
3. 단골
4. 탐험
5. 추천 및 월드컵
6. 리뷰 및 정보 기여
7. 함께 먹기
8. 숨겨진 업적

업적은 기본적으로 계정당 한 번만 달성할 수 있다.
반복 활동을 보여주고 싶을 때는 같은 업적을 반복 지급하지 않고 단계형 업적으로 구성한다.

```text
점심 기록가 I
점심 기록가 II
점심 기록가 III
```

### 3.2 업적 보상
업적 보상은 다음 세 가지로 제한한다.
업적 포인트
업적 수집 정도를 나타내는 점수다.

* 일반 업적: 10점
* 중급 업적: 20점
* 고급 업적: 40점
* 특별 업적: 30점
* 숨겨진 업적: 20점

업적 포인트는 현금이나 상품으로 교환하지 않는다.
프로필 칭호
특정 업적을 달성하면 프로필에 표시할 칭호가 해금된다.

```text
정홍천
[센텀 미식가]
```

사용자는 해금한 칭호 중 하나만 대표 칭호로 선택할 수 있다.
프로필 배지
업적 카테고리별 배지를 프로필에 표시한다.

```text
🍚 방문 배지
🧭 탐험 배지
✍️ 기여 배지
👥 동행 배지
🏆 월드컵 배지
```

공개 프로필에는 사용자가 선택한 대표 배지 3개만 표시한다.

## 4. 시작 업적
### 4.1 첫 숟가락

* 조건: 첫 번째 방문 기록 완료
* 기준 이벤트: `VISIT_COMPLETED`
* 보상: 10점
* 공개 여부: 공개
* 설명: 앤시점심기술에서 첫 점심 기록을 남겼습니다.

방문 예정 등록만으로는 달성되지 않고, 식사 후 `다녀왔어요` 처리가 완료되어야 한다.

### 4.2 점심기술 입문자

* 조건: 즉시 추천 기능을 처음 사용
* 기준 이벤트: `RECOMMENDATION_CREATED`
* 보상: 10점
* 칭호: `점심기술 입문자`
* 설명: 점심 결정을 기술에 맡겨보았습니다.

추천 결과를 보기만 해도 달성된다.

### 4.3 취향 발견

* 조건: 메뉴 월드컵 첫 완료
* 기준 이벤트: `WORLDCUP_COMPLETED`
* 보상: 10점
* 설명: 오늘 가장 먹고 싶은 메뉴를 찾아냈습니다.

월드컵을 중간에 종료한 경우에는 달성되지 않는다.

### 4.4 기록의 시작

* 조건: 첫 리뷰 작성
* 기준 이벤트: `REVIEW_CREATED`
* 보상: 10점
* 설명: 첫 번째 점심 평가를 남겼습니다.

삭제되거나 신고 처리된 리뷰는 달성 조건에서 제외한다.

### 4.5 혼밥 탈출

* 조건: 함께 먹기 약속 첫 완료
* 기준 이벤트: `MEAL_GROUP_COMPLETED`
* 보상: 10점
* 설명: 동료와 함께한 첫 번째 점심입니다.

방 참가만으로 달성되지 않고 실제 식사 완료 처리가 필요하다.

## 5. 방문 업적
### 5.1 점심 기록가 I

* 조건: 누적 방문 기록 5회
* 보상: 10점
* 진행도 표시: `3 / 5`
* 설명: 점심 기록을 5번 남겼습니다.

### 5.2 점심 기록가 II

* 조건: 누적 방문 기록 20회
* 보상: 20점
* 진행도 표시: `14 / 20`
* 설명: 점심 기록이 어느새 20번을 넘었습니다.

### 5.3 점심 기록가 III

* 조건: 누적 방문 기록 50회
* 보상: 40점
* 칭호: `점심 기록 전문가`
* 설명: 50번의 점심을 기록했습니다.

### 5.4 점심은 계속된다

* 조건: 누적 방문 기록 100회
* 보상: 40점
* 칭호: `100끼의 사나이` 또는 `100끼의 기록자`
* 설명: 앤시점심기술과 함께 100번의 점심을 먹었습니다.

성별 표현을 피하려면 기본 칭호는 `100끼의 기록자`로 사용한다.

### 5.5 이번 달도 잘 먹었습니다

* 조건: 한 달 동안 방문 기록 10회
* 보상: 20점
* 설명: 한 달 동안 10번의 점심을 기록했습니다.

휴가나 병가 등 근태와 연결되어 보이지 않도록 `개근`, `출석` 같은 표현은 사용하지 않는다.

### 5.6 점심 루틴

* 조건: 서로 다른 날짜에 10일 이상 방문 기록
* 보상: 20점
* 설명: 점심 기록이 자연스러운 습관이 되었습니다.

연속 기록이 아니라 누적 활동일 기준으로 계산한다.

## 6. 단골 업적
### 6.1 여기 괜찮은데?

* 조건: 같은 식당 3회 방문
* 보상: 10점
* 설명: 한 식당을 세 번 방문했습니다.

### 6.2 단골손님

* 조건: 같은 식당 10회 방문
* 보상: 20점
* 칭호: `단골손님`
* 설명: 이제 메뉴판을 보지 않아도 주문할 수 있을 것 같습니다.

### 6.3 사장님이 알아볼 듯

* 조건: 같은 식당 20회 방문
* 보상: 40점
* 칭호: `사장님이 알아볼 듯`
* 설명: 이 정도면 직원보다 먼저 출근했을 수도 있습니다.

### 6.4 한결같은 취향

* 조건: 같은 메뉴를 총 10회 선택
* 보상: 20점
* 설명: 좋아하는 메뉴가 확실한 사람입니다.

같은 식당이 아니라 표준화된 메뉴 카테고리 또는 연결된 메뉴 ID를 기준으로 계산한다.

## 7. 탐험 업적
### 7.1 새로운 맛

* 조건: 처음 방문하는 식당 3곳
* 보상: 10점
* 설명: 새로운 식당 세 곳을 방문했습니다.

### 7.2 점심 개척자

* 조건: 서로 다른 식당 10곳 방문
* 보상: 20점
* 칭호: `점심 개척자`
* 설명: 익숙한 길을 벗어나 새로운 점심을 찾았습니다.

### 7.3 센텀 탐험대

* 조건: 서로 다른 식당 20곳 방문
* 보상: 40점
* 칭호: `센텀 탐험대`
* 설명: 센텀 주변의 점심 지도를 넓혀가고 있습니다.

### 7.4 센텀 미식가

* 조건: 서로 다른 식당 40곳 방문
* 보상: 40점
* 칭호: `센텀 미식가`
* 설명: 주변 식당을 물어보면 가장 먼저 떠오르는 사람입니다.

### 7.5 편식은 없습니다 I

* 조건: 서로 다른 음식 카테고리 3종 방문
* 보상: 10점

예시 카테고리:

* 한식
* 중식
* 일식
* 양식
* 분식
* 패스트푸드
* 샐러드
* 아시아 음식

### 7.6 편식은 없습니다 II

* 조건: 서로 다른 음식 카테고리 6종 방문
* 보상: 20점
* 칭호: `메뉴 수집가`

### 7.7 조금만 더 걸어볼까요?

* 조건: 회사 기준 도보 거리 800m 이상 식당 첫 방문
* 보상: 20점
* 설명: 가까운 곳을 벗어나 새로운 점심을 찾아갔습니다.

비나 폭염 등 날씨를 업적 조건에 직접 사용하지 않는다.

### 7.8 신상 발견

* 조건: 서비스에 등록된 지 30일 이내인 식당 방문
* 보상: 20점
* 설명: 새로 등록된 식당을 빠르게 방문했습니다.

### 7.9 숨은 맛집 발견

* 조건: 전체 방문 횟수가 적은 식당을 방문
* 구체 조건: 최근 60일간 전체 방문 기록 5회 이하인 식당
* 보상: 20점
* 설명: 아직 많은 사람이 찾지 않은 식당을 발견했습니다.

사용자 수가 적은 초기에는 조건을 비활성화하거나 기준을 낮춘다.

## 8. 추천 및 메뉴 월드컵 업적
### 8.1 기술을 믿어봅니다

* 조건: 추천받은 식당을 처음 방문 완료
* 이벤트 흐름:

```text
추천 결과 생성
→ 추천 식당 선택
→ 방문 예정 등록
→ 다녀왔어요 완료
```

* 보상: 10점
* 설명: 추천 결과를 실제 점심 선택으로 이어갔습니다.

### 8.2 알고리즘 신봉자 I

* 조건: 추천을 통해 식당 5회 방문
* 보상: 20점
* 칭호: `알고리즘 신봉자`

### 8.3 알고리즘 신봉자 II

* 조건: 추천을 통해 식당 20회 방문
* 보상: 40점
* 설명: 오늘 점심은 이제 알고리즘이 더 잘 알고 있습니다.

### 8.4 첫눈에 결정

* 조건: 첫 번째 추천 결과를 다시 추천 없이 바로 선택하고 방문 완료
* 보상: 20점
* 설명: 고민 없이 첫 추천을 선택했습니다.

한 번 선택한 것만으로 달성하지 않고 실제 방문 완료까지 필요하다.

### 8.5 월드컵 참가자

* 조건: 메뉴 월드컵 5회 완료
* 보상: 10점
* 설명: 메뉴 토너먼트에 다섯 번 참가했습니다.

### 8.6 메뉴 월드컵 베테랑

### 8.7 우승 메뉴 실행력

* 보상: 30점
* 설명: 토너먼트 결과를 실제 점심으로 이어갔습니다.

월드컵 완료 후 일정 시간 안에 연결된 식당을 선택하고 방문해야 한다.

```text
월드컵 완료 당일 17:00까지
```

### 8.8 취향 확실하시네요

* 보상: 20점
* 설명: 우승 메뉴가 자꾸 익숙합니다.

숨겨진 업적은 달성 전까지 이름과 조건을 공개하지 않는다.
화면에는 다음과 같이 표시한다.

```text

```

### 11.1 월요일부터 든든하게

시스템 부하를 막기 위해 추천 버튼에 짧은 쿨다운을 적용한다.

### 11.3 결국 처음으로

* 조건: 여러 번 다시 추천한 뒤 최초 추천 식당을 최종 선택하고 방문

* 달성 설명: 돌고 돌아 처음 만난 식당으로 돌아왔습니다.

추천 세션 동안 등장한 식당 이력을 저장해야 판정할 수 있다.

### 11.4 오늘도 그곳

안전을 고려하여 서비스가 공식적으로 추천하는 최대 거리 안에서만 달성 가능하게 한다.

* 보상: 30점

## 12. 업적 진행도 규칙
### 12.1 진행도 표시
수치형 업적은 현재 진행도를 표시한다.

```text
점심 기록가 II
14 / 20회

██████████████░░░░░░
70%
```

숨겨진 업적은 달성 전 진행도를 표시하지 않는다.

### 12.2 단계형 업적 표시
같은 계열의 업적은 하나의 묶음으로 보여준다.

```text
점심 기록가

✓ I · 방문 5회
✓ II · 방문 20회
□ III · 방문 50회
□ 특별 · 방문 100회
```

업적 목록이 지나치게 길어 보이지 않도록 단계형 업적은 한 카드 안에 표현한다.

### 12.3 달성 처리 방식
업적은 조건 충족 즉시 자동 달성된다.
별도의 `보상 받기` 버튼은 만들지 않는다.

```text
다녀왔어요 처리
→ 서버에서 방문 저장
→ 관련 업적 조건 확인
→ 업적 달성 저장
→ 달성 알림 표시
```

사용자가 보상을 직접 수령하게 하면 누락되거나 불필요한 클릭이 늘어나므로 자동 지급 방식이 적절하다.

## 14. 어뷰징 방지 규칙
### 14.1 방문 기록

* 같은 사용자가 같은 날짜에 같은 식당에서 얻는 방문 카운트는 최대 1회
* 방문 예정 상태는 카운트하지 않음
* `다녀왔어요` 완료된 기록만 인정
* 취소된 방문은 제외
* 관리자가 삭제한 비정상 기록은 업적 진행도에서도 차감

### 14.2 리뷰

* 동일한 방문에 대해 리뷰 1개만 인정
* 내용 없는 평가 반복 등록 방지
* 삭제된 리뷰는 카운트 제외
* 신고 후 숨김 또는 삭제된 리뷰는 카운트 제외
* 본인이 작성한 리뷰를 수정해도 추가 카운트하지 않음

### 14.3 정보 등록 및 제보

* 등록 즉시가 아니라 승인 완료 시 카운트
* 같은 내용의 반복 제보는 한 건만 인정
* 본인이 등록한 정보를 삭제 후 재등록해도 중복 인정하지 않음
* 관리자가 반려한 정보는 카운트하지 않음

### 14.4 함께 먹기

* 방 생성만으로 업적을 지급하지 않음
* 실제 완료된 약속만 인정
* 같은 구성원으로 같은 날 여러 방을 만들어도 1회만 인정
* 취소되거나 인원이 모이지 않은 약속은 제외

### 14.5 월드컵

* 월드컵의 모든 선택을 완료해야 1회로 인정
* 같은 사용자가 짧은 시간 동안 반복 실행한 경우 쿨다운 적용 가능
* 업적 목적의 무한 반복을 막기 위해 하루 인정 횟수 제한

권장 기준:

```text
월드컵 완료 업적 진행도: 하루 최대 3회
취향 데이터 반영: 하루 최대 2회
```

사용 자체는 제한하지 않지만 업적과 선호도 반영 횟수만 제한한다.

## 15. 데이터 구조 제안
### 15.1 achievements
업적 정의 테이블이다.

```text
id
code
name
description
hidden_description
category
tier
target_value
point_reward
title_reward_id
is_hidden
is_active
sort_order
created_at
updated_at
```

예시:

```text
code: VISIT_TOTAL_20
name: 점심 기록가 II
category: VISIT
target_value: 20
point_reward: 20
is_hidden: false
```

### 15.2 user_achievement_progress
사용자별 진행도를 저장한다.

```text
id
user_id
achievement_id
current_value
target_value
progress_data
updated_at
```

`progress_data`에는 업적마다 필요한 부가 정보를 JSON으로 저장할 수 있다.

```json
{
  "visitedRestaurantIds": ["restaurant-1", "restaurant-4"],
  "categoryIds": ["korean", "japanese"]
}
```

단순 카운트만 필요한 업적은 별도의 JSON 데이터를 저장하지 않아도 된다.

### 15.3 user_achievements
달성 완료 정보를 저장한다.

```text
id
user_id
achievement_id
earned_at
trigger_event_id
is_new
created_at
```

`is_new`는 사용자가 아직 달성 알림이나 상세 화면을 확인하지 않았는지 표시한다.

### 15.4 achievement_events
업적 판정에 사용한 이벤트 기록이다.

```text
id
user_id
event_type
event_key
reference_type
reference_id
payload
occurred_at
processed_at
```

예시 이벤트:

```text
VISIT_COMPLETED
REVIEW_CREATED
MENU_CREATED_APPROVED
RESTAURANT_CREATED_APPROVED
RESTAURANT_INFO_UPDATED_APPROVED
RECOMMENDATION_ACCEPTED
WORLDCUP_COMPLETED
WORLDCUP_WINNER_VISITED
MEAL_GROUP_COMPLETED
```

`event_key`를 고유값으로 지정해 같은 요청이 두 번 처리되어도 업적 진행도가 중복 증가하지 않도록 한다.
예시:

```text
VISIT_COMPLETED:visit_12345
```

### 15.5 titles
칭호 정의 테이블이다.

```text
id
code
name
description
achievement_id
is_active
```

사용자 테이블에는 대표 칭호만 저장한다.

```text
users.selected_title_id
```

## 16. 서버 처리 원칙
업적 판정은 브라우저에서 처리하지 않는다.

```text
브라우저
→ 방문 완료 요청
→ 서버에서 방문 데이터 저장
→ 업적 이벤트 생성
→ 업적 진행도 갱신
→ 달성 여부 판정
→ 결과 반환
```

클라이언트가 다음과 같은 값을 직접 전달해서는 안 된다.

```text
achievementCompleted: true
progressIncrement: 1
pointReward: 20
```

클라이언트는 실제 행동만 요청하고, 업적 계산은 서버가 신뢰할 수 있는 DB 데이터를 기준으로 처리한다.

## 18. 월간 업적과 일반 업적 구분
월간 리뷰왕, 개척왕, 메뉴 수집왕은 영구 업적과 분리한다.
영구 업적
한 번 달성하면 계속 보유한다.

```text
점심 개척자
메뉴 수집가
점심 평론가
```

월간 배지
한 달 동안의 활동을 기준으로 선정한다.

```text
2026년 8월 리뷰왕
2026년 8월 개척왕
2026년 8월 메뉴 수집왕
```

월간 배지는 프로필 기록에 남지만 대표 칭호로 선택할 수 있는 기간은 해당 월과 다음 달까지로 제한할 수 있다.
월간 랭킹은 활동량이 적은 직원에게 부담이 될 수 있으므로 정확한 순위보다 다음과 같이 표시하는 것도 좋다.

```text
8월 점심 개척왕
새로운 식당 방문 1위
```

또는 공동 수상 조건을 둔다.

```text
신규 식당 3곳 이상 방문한 직원 모두
'8월 점심 개척단' 배지 지급
```

사내 서비스에서는 경쟁보다 공동 달성형이 더 부담이 적다.

## 19. 핵심 운영 원칙

1. 업적을 위해 서비스를 사용하는 것이 아니라 서비스를 사용하다 보면 업적이 달성되어야 한다.
2. 휴가, 병가, 재택근무 등 근태를 추측할 수 있는 업적은 만들지 않는다.
3. 리뷰와 정보 등록 업적은 승인된 유효 데이터만 인정한다.
4. 공개 프로필에는 사용자가 선택한 칭호와 배지만 표시한다.
5. 업적 포인트는 현금성 보상이나 인사 평가와 연결하지 않는다.
6. 월드컵 결과는 실제 식당 추천과 자연스럽게 연결한다.
7. 모든 업적 판정은 서버에서 처리한다.
8. 초기에는 핵심 업적만 구현하고 실제 사용 패턴을 확인한 뒤 추가한다.

## 20. 최종 권장 구성
앤시점심기술의 게임·업적 시스템은 다음 구조가 가장 적절하다.

```text
오늘의 메뉴 월드컵
→ 우승 메뉴 결정
→ 관련 식당 추천
→ 식당 선택
→ 함께 먹기 또는 개인 방문
→ 다녀왔어요
→ 방문·탐험·월드컵 업적 진행
→ 리뷰 작성
→ 리뷰·기여 업적 진행
```

게임과 업적이 독립적으로 존재하는 것이 아니라, 서비스의 핵심 흐름인 추천 → 결정 → 식사 → 기록 안에 자연스럽게 포함되어야 한다.
핵심은 업적 개수가 아니라 사용자가 다음과 같은 느낌을 받게 만드는 것이다.
그냥 점심 먹고 기록했을 뿐인데 뭔가 하나씩 쌓이고 있다.
이 방향이면 앤시점심기술의 가벼운 사내 서비스 분위기를 유지하면서도 장기적으로 사용할 이유를 만들 수 있다.

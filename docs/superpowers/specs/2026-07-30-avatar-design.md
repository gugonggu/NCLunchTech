# 아바타 기능 설계

## 목표

직원이 2D 아바타를 커스터마이징하고, 내 정보와 리뷰에서 닉네임과 함께 보여준다.

## 3D 아바타 관련 결정 (2026-07-30)

원래 이 설계는 2D(DiceBear)와 3D(Ready Player Me) 두 가지 타입을 지원할 계획이었다. 3D 계획을 시작하려는 시점에 **Ready Player Me가 2026-01-31부로 서비스를 완전히 종료**한 사실을 확인했다(2025-12-19 넷플릭스 인수 발표 직후 종료 공지, 호스팅된 에디터·REST API 전부 오프라인). 대안으로 조사한 Avatar SDK의 MetaPerson Creator는 기술 구조(iframe + postMessage + GLB)는 유사하지만, 소규모(15~20인) 사용 시 실제 비용과 서비스 안정성이 자사 마케팅 자료 외에는 확인되지 않았다. 이 불확실성을 사용자에게 보고한 뒤, **3D 아바타는 이번 범위에서 완전히 제외하기로 결정**했다. 이 문서는 2D 전용으로 범위를 좁혀 갱신한다.

## 범위

- 직원은 DiceBear 한 스타일의 파트(머리·머리색·피부색·눈·입·옷·액세서리 등)를 선택해 2D 아바타를 조합한다.
- "내 정보"에서 인터랙티브 에디터(파트 선택 폼 + 실시간 미리보기)로 커스터마이징한다.
- 리뷰 작성자 표시에는 정적 미리보기 이미지만 보여준다.
- 아바타를 설정하지 않은 직원은 고정된 기본 아바타 이미지로 표시한다.

## 제외 범위

- 리뷰 외의 화면(오늘 같이 먹기 목록, 약속 참여자 목록, 동료 초대 검색 등)에 아바타를 노출하는 것은 이번 범위가 아니다. 리뷰 반응을 보고 이후 단계에서 확장한다.
- 2D 파트를 직접 그리거나 외주 제작하는 것, DiceBear 외 다른 2D 아바타 라이브러리 검토는 하지 않는다.
- **3D 아바타는 다루지 않는다** (위 "3D 아바타 관련 결정" 참고 — 외부 서비스 종료·대안 비용 불확실성으로 범위에서 제외).
- 아바타 관련 통계, 랭킹, 도감 연동은 다루지 않는다.

## 데이터 모델 (구현됨)

`employees` 테이블에 컬럼을 추가했다 (`supabase/migrations/0063_employee_avatar.sql`).

- `avatar_type text`: `'2d'` 또는 `null`(미설정 = 기본 아바타 표시). 3D 타입은 없다.
- `avatar_options jsonb`: DiceBear 트레잇 선택값. 미설정이면 `null`.
- `avatar_storage_path text`: Supabase Storage(`avatars` 버킷) 경로. URL은 저장하지 않고 조회 시점에 `getPublicUrl()`로 파생시킨다(`review-photos`와 동일한 기존 컨벤션). 스펙 초안의 `avatar_preview_url`(URL 직접 저장) 대신 이 방식을 따랐다.

`check` 제약으로 `avatar_type`이 `2d`일 때만 `avatar_options`가 `null`이 아닐 수 있음을 강제한다.

## 서버 동작 (구현됨)

### 저장

1. 서버 액션(`updateAvatar`)이 세션의 직원을 확인한다.
2. 받은 옵션 값이 고정된 DiceBear 스타일(`avataaars`)의 허용 트레잇 목록에 있는지 화이트리스트로 검증한다.
3. `avatar_type = '2d'`, `avatar_options`를 저장한다.
4. 서버에서 `@dicebear/core`로 동일 옵션의 SVG를 생성해 PNG로 변환하고, `avatars/{employeeId}.png` 경로로 Supabase Storage에 덮어쓴다(`upsert: true`, `cacheControl: "0"`으로 재저장 시 캐시로 인한 미갱신을 방지).
5. 업로드에 성공하면 `avatar_storage_path`를 갱신한다. 실패하면 옵션 저장은 유지하고 `avatar_storage_path`는 이전 값을 그대로 둔 채 안내 메시지를 반환한다.

### 조회

- "내 정보"는 `avatar_type`, `avatar_options`, 파생된 미리보기 URL을 모두 조회해 에디터와 현재 아바타를 표시한다.
- 리뷰 목록/상세는 작성자의 미리보기 URL만 조회한다(`getAvatarPreviewUrls` 배치 조회). 값이 없으면 고정된 기본 아바타 이미지(`/avatar-default.png`)를 사용한다.

## 클라이언트 UI (구현됨)

### 내 정보 (`/me`)

- 트레잇별 폼으로 커스터마이징한다: 머리스타일·눈·입·옷스타일·액세서리·수염은 한글 라벨 드롭다운, 머리색·피부색·옷색은 색상 스와치 버튼그릿.
- `@dicebear/core`로 클라이언트에서 즉시 계산하는 실시간 미리보기(`toDataUri()`)를 보여준다.
- 아직 아바타가 없으면 기본 아바타 이미지를 보여준다.

### 리뷰

- 작성자 표시 옆에 미리보기 이미지(없으면 기본 아바타)를 작게 보여준다(`<AvatarImage>`).

## 외부 서비스

- **DiceBear**: `@dicebear/core`/`@dicebear/collection`(정확히 `9.4.3`으로 버전 고정, 두 패키지가 서로 다른 major일 때 호환이 깨질 수 있어서) npm 패키지로 서버·클라이언트 모두에서 로컬 생성한다. 외부 API 호출이 없어 비용·가용성 문제가 없다.
- ~~Ready Player Me~~: 2026-01-31부로 서비스가 완전히 종료되어 채택하지 않았다. 3D 아바타는 이 기능에서 다루지 않는다(위 "3D 아바타 관련 결정" 참고).

## 오류 및 경계 조건

- 트레잇 값은 서버 화이트리스트로만 검증하고, 허용되지 않은 값은 거부한다.
- 미리보기 이미지 생성(PNG 변환/업로드)이 실패해도 옵션 저장 자체는 성공시키고, 미리보기는 이전 값을 유지하며 재시도 안내를 표시한다.
- 미리보기 이미지는 직원별 고정 경로에 덮어쓰므로 별도 정리(cleanup) 작업이 필요 없다.
- 저장된 `avatar_options`가 이후 트레잇 목록 변경으로 무효화되더라도, 조회 시 재검증해 무효하면 `null`로 취급한다(자가 복구).

## 검증 (구현됨)

- 순수 검증 로직: DiceBear 트레잇 화이트리스트, 라벨 맵 완전성(모든 DiceBear 값에 한글 라벨이 있는지)을 단위 테스트한다.
- 저장 흐름: 미리보기 생성 성공/실패 각 케이스에서 저장되는 DB 값을 단위 테스트한다(Storage·렌더는 모킹, 단 render.ts 자체는 실제 sharp/dicebear로 렌더링해 PNG 시그니처·결정론성을 검증).
- UI: 내 정보의 폼/스와치, 기본 아바타 표시, 리뷰 목록의 미리보기 이미지 렌더링을 컴포넌트 테스트한다.
- 전체 검증: lint, typecheck, 단위/컴포넌트 테스트, build를 실행한다.

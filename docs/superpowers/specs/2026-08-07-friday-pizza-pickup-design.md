# 금요일 피자 파티와 포장 식사 방식 설계

## 목표

매주 금요일(Asia/Seoul)에만 홈에서 파파존스 센텀시티점의 1+1 행사를 알리고, 직원이 공개 `포장` 약속을 빠르게 만들 수 있게 한다. 대표 주문자는 한 명이며, 참여자들은 2~3명 이상 함께 매장으로 가서 픽업한 뒤 같이 식사한다.

## 범위

- `appointments.meal_type`에 `pickup`을 정식 식사 방식으로 추가한다.
- 약속 생성·상세·목록·관련 화면에서 `pickup`을 사람이 읽는 "포장"으로 일관되게 표시한다.
- 홈에 금요일 전용 피자 파티 카드를 추가한다.
- 카드에서 파파존스 센텀시티점이 선택된 공개 포장 약속 생성 화면으로 이동하며, 안내 메모를 채운다.

다음은 범위에서 제외한다.

- 파파존스 주문·결제·주문 링크 연동
- 대표 주문자 또는 비용 정산을 별도 데이터로 관리하는 기능
- 관리자가 임의의 반복 프로모션을 만들고 끄는 관리 화면
- 금요일 외의 배너 노출

## 전제 조건

파파존스 센텀시티점은 활성 상태의 기존 `restaurants` 레코드여야 한다. 레코드가 없으면 기존 관리자 식당 등록 흐름으로 먼저 등록한다. 이벤트 카드는 정확히 그 활성 레코드를 찾을 수 있을 때만 노출해, 잘못된 식당으로 약속이 생성되는 일을 막는다.

## 사용자 흐름

1. 홈 서버 페이지가 현재 시각을 Asia/Seoul 기준으로 판단한다.
2. 금요일이고 활성 파파존스 센텀시티점 레코드를 찾으면, 공지 아래·기본 히어로 위에 피자 파티 카드를 표시한다.
3. 카드의 `포장 약속 만들기`를 누르면 해당 식당이 선택된 `/appointments/new`으로 이동한다.
4. 생성 폼은 식사 방식을 `포장`으로 기본 선택하고, 공개 모집을 기본 활성화하며, 다음 메모를 기본값으로 표시한다: `1+1 이벤트 · 대표 주문 후 2~3명이 함께 픽업, 함께 식사해요.`
5. 사용자는 시간·정원·메모를 조정한 뒤 기존 약속 생성 흐름으로 공개 약속을 만든다.

## UI

카드는 기존 홈의 오렌지 계열 시각 언어를 따르되, 피자 조각 이모지와 짧은 제목으로 한정 행사를 구분한다.

- 레이블: `이번 주 금요일`
- 제목: `🍕 금요일 피자 파티`
- 설명: `파파존스 센텀시티점 1+1 · 같이 주문하고 포장해요`
- 보조 문구: `대표 주문 후 함께 픽업, 함께 식사`
- CTA: `포장 약속 만들기`

카드는 로그인한 직원에게만 표시된다. 금요일이 아니거나 식당 레코드가 없거나 비활성화되면 렌더링하지 않는다.

## 데이터와 검증

- 새 마이그레이션은 `appointments.meal_type` 제약 조건 또는 enum에 `pickup`을 추가한다.
- TypeScript의 `AppointmentMealType`과 서버 입력 검증은 `pickup`만 허용하며, 임의의 값은 기존과 같이 거부한다.
- 기존 `dine_in`과 `delivery` 약속 데이터·동작은 변경하지 않는다.
- 카드는 조회 전용이며 DB에 이벤트 상태나 개인 데이터를 저장하지 않는다.

## 오류 처리

- 카드가 가리키는 식당은 서버에서 활성 레코드인지 다시 검증한다.
- 식당이 비활성화되었거나 존재하지 않으면 기존 약속 생성 오류 흐름을 사용한다.
- 비금요일 직접 URL 접근은 막지 않는다. 사용자는 일반 약속 생성 화면에서 포장을 선택할 수 있다.

## 검증

- `pickup` 파싱과 거부 입력에 대한 단위 테스트
- 약속 생성 페이지에서 포장 옵션과 피자 카드 전달 기본값을 확인하는 렌더링 테스트
- 홈에서 금요일/비금요일 및 식당 존재 여부에 따른 카드 노출 테스트
- 프로젝트의 lint, typecheck, test, build 실행

# 가중치 룰렛 고도화 설계

## 목표

직원이 룰렛 후보 식당을 추가·삭제하고, 식당별 칸 수를 조절해 당첨 확률을 직접 구성할 수 있게 한다. 편집한 목록을 그대로 다시 돌리거나, 현재 추천 조건으로 새 목록을 재구성할 수 있어야 한다.

## 범위

- 룰렛 화면에서 후보 식당 목록을 열고 편집한다.
- 후보마다 최소 1칸의 가중치를 가진다.
- 각 후보의 확률은 `후보 칸 수 / 전체 칸 수`으로 표시한다.
- 총 칸 수는 후보 가중치 합계이며 최대 64칸이다.
- 후보 삭제는 별도 삭제 동작으로 제공하며, 0칸 가중치는 허용하지 않는다.
- 현재 추천 조건을 통과한 식당을 후보로 추가할 수 있다.
- `현재 목록으로 다시 돌리기`는 편집한 후보와 가중치를 유지한다.
- `재구성하기`는 현재 추천 조건의 후보로 목록을 다시 만들고 모든 가중치를 1칸으로 초기화한다.

## 제외 범위

- 개인별 후보 목록·가중치의 DB 저장 또는 다음 방문에서의 복원
- 추천 조건 밖 식당의 임의 추가
- 64칸을 넘는 확률 가중치

## 데이터와 상태

서버는 현재 추천 조건을 통과한 후보의 `id`, `name`, `category`를 룰렛 컴포넌트에 전달한다. 클라이언트는 다음 상태를 관리한다.

```ts
type RouletteEntry = { id: string; name: string; weight: number };
```

초기 목록은 기존 서버 추천 후보를 모두 1칸으로 구성한다. 편집 상태는 페이지를 떠나거나 `재구성하기`를 실행할 때만 초기화된다. 당첨 식당은 가중치 기반 클라이언트 추첨으로 선택하며, 결정·동행·투표 동작은 선택된 식당 ID로 기존 서버 액션/링크를 호출한다.

## 제약과 오류 처리

- 가중치 감소는 1칸 아래로 내려가지 않는다.
- 증가로 전체 64칸을 넘기지 않는다.
- 마지막 후보는 삭제할 수 없다.
- 추가할 후보가 없으면 식당 추가 UI는 비활성 안내를 표시한다.
- 재구성으로 후보가 없으면 기존 추천 페이지의 빈 결과 상태를 유지한다.

## UI 흐름

1. 룰렛 상단에 현재 총 칸 수와 후보 수를 표시한다.
2. `후보 편집`에서 식당별 `− / 칸 수 / +`, 확률, 삭제를 제공한다.
3. `식당 추가`에서 아직 목록에 없는 현재 조건 후보를 선택한다.
4. 편집 후 `현재 목록으로 다시 돌리기`를 누르면 같은 엔트리 상태로 회전을 다시 시작한다.
5. `재구성하기`는 확인 없이 후보 전체를 1칸씩인 초기 목록으로 바꾼다.
6. 원형 룰렛 조각은 각 가중치 비율에 맞게 렌더링하며, 라벨 너비와 배치는 조각 비율에 따라 계산한다.

## 검증

- 가중치 변경, 총 64칸 상한, 최소 1칸, 마지막 후보 삭제 방지를 단위 테스트한다.
- 가중치 기반 추첨이 0 미만/범위 밖 후보를 선택하지 않음을 테스트한다.
- 후보 편집 UI에서 확률·가중치·추가·삭제·재회전·재구성을 컴포넌트 테스트한다.
- `npm.cmd run lint`, `npm.cmd run typecheck`, `npm.cmd run test`, `npm.cmd run build`를 실행한다.
